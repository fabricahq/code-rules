How to read the response

ok: true means the Go function returned no error. The group-ID adapter echoes the validated input as value. Rule paths return their group; selections return a sorted list or an unexpanded wildcard. Metadata returns name, description, and an ordered whenToRead list.

ValidationError is a returned Go error for invalid domain input. AdapterError means the request could not reach a function, for example because the outer request was malformed. Metadata is sent as document text, so malformed metadata JSON reaches Go and produces a ValidationError.

A nested validation error keeps the full rule path in its message. Go callers can still find its type with errors.As. Expected input errors stay in the response. Operational failures are reported once at the boundary, using log/slog on stderr.

Walk through the change

Follow the metadata through Go

1. Read the document

ParseGroupMetadata checks JSON syntax and requires an object. It reads raw fields before decoding their values so field names stay case-sensitive and unknown values can be ignored.

Try Malformed JSON or Unknown field. Duplicate JSON keys use their last value, matching TypeScript.

2. Validate in order

Group-level license and licenses fields fail first. Then Go checks the name, description, and every guidance entry before checking for duplicate guidance.

Try Blank before duplicate. The error points to the blank entry’s original index.

3. Return an owned value

GroupMetadata contains the name, description, and WhenToRead []string. Text is trimmed at both ends; internal spacing and list order stay intact. Empty guidance returns an empty array. Errors return no partial value.

The parser returns the existing ValidationError type. It does not log, read files, or write files.

What this slice establishes

This slice parses a group’s _group.json contents. It does not find groups, read files, expand wildcards, or parse rule Markdown. The 53 new metadata cases and 87 identity cases run against both the TypeScript reference and the real Go executable.

Contract coverage and remaining work

These checks provide partial evidence for formats.identities.05: metadata field presence, null, and unknown fields. Group metadata is also a prerequisite for builds.resolve.04. Full capability acceptance remains pending; no acceptance criteria or baseline changed.

Cross-runtime string parity currently covers Unicode scalar text. Lone UTF-16 surrogates in JSON require a separate compatibility decision before the full configuration contract can be accepted.
