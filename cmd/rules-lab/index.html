How to read the result

identity is a comparison key for duplicate sources. GitHub paths compare in lowercase; GitLab paths retain case. Standard HTTPS and git-user SSH transports share the same known-host identity.

web contains root, tree, file, and raw endpoints. A custom host, port, or SSH user may produce web: null. This is a valid address with no recognized browser convention.

Link building returns a URL string, or null when no web convention is known. Encoded path segments retain their slash boundaries.

No repositories are fetched, and no files are read or written. A valid address does not establish access or existence.

Walk through this PR

Three things to inspect

1. One repository, several addresses

Try GitHub HTTPS, GitHub SSH, and GitHub SCP. Their identities match. GitLab retains the case of nested group paths.

2. Reject ambiguity early

Try Credentials, Traversal, and Encoded slash. The parser checks authored path segments before a URL parser could normalize them away.

3. Known links, honest limits

Switch to link building. Try Raw image, Encoded file, and Unknown host. A null result prevents callers from guessing a host's web routes.
