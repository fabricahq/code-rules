How to read the result

ParseGitRef returns either a lowercase 40-digit commit SHA or a tag name beginning with refs/tags/. A bare main means the tag named main. Explicit branch refs are rejected.

TagVersion takes an unqualified tag name. It removes one optional lowercase v and retains prerelease and build suffixes. Go returns (version, true) when recognized.

The value object shows both Go return values: version and recognized. For an incomplete version, these are "" and false. ok: true means the function returned without an error; ok: false means an error occurred. A non-version tag is a normal result, not an error.

No refs are resolved, repositories fetched, or files read or written. These functions do not establish that a revision exists. npm ranges such as ^1.2.3 belong to a later slice.

Walk through this PR

Three things to inspect

1. Remove ref ambiguity

Try Full SHA, Main is a tag, and Short hex. A 4-39 digit hexadecimal name needs the explicit tag prefix; a full 40-digit SHA means a commit.

2. Keep exact names

Try Explicit hex tag and Nested tag. Tag case and spelling stay intact. Branch ref and Traversal show typed validation errors.

3. Recognize complete versions

Switch to version recognition. Compare Prerelease + build with Partial version and Leading zero. A non-version tag returns recognized: false without throwing an error.

What is ready to review

Only exact refs and strict version tags are new here. Earlier operations remain in regression tests. Range matching, version ordering, and Git resolution remain for later PRs.

Shared fixtures compare exact values and errors with independent expectations and the pinned TypeScript implementation. No runtime dependencies or approved behavior differences are added.
