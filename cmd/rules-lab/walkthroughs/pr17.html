How to read the result

ParseVersionConstraint returns a reusable constraint and an error. The adapter shows its String() value, trimming surrounding whitespace and preserving internal spacing.

Matches returns (bool, error). A complete version inside the constraint returns (true, nil); a complete version outside it returns (false, nil).

ok: true means Go returned no error. value: false means a valid version did not match. Invalid constraint syntax or an incomplete version returns an error, shown as ok: false.

No releases are fetched or selected. This PR validates constraints and checks individual versions; it reads and writes no project files.

What our wrapper adds

1. Trim surrounding whitespace

Try Trim spaces. The parser removes leading and trailing whitespace while preserving internal spacing.

2. Validate release tags

Tag prefix accepts v1.2.3. Invalid version returns a validation error for the incomplete release 1.2, with your error location.

3. Separate nonmatches from errors

Exact match returns true. Different patch returns false without an error. Invalid inputs return an error instead.

An intentional syntax change

The Go target uses HashiCorp syntax and matching behavior. The pinned TypeScript reference retains npm syntax. This is a user-approved format change, not a compatibility layer.

For example, replace npm ^1.2.3 with >= 1.2.3, < 2.0.0 for stable releases. Replace ~1.2.3 with ~> 1.2.3. OR expressions have no direct equivalent. Check prerelease intent when converting.

Ten focused fixtures cover our input boundaries and representative integration with go-version. Operator and version-ordering semantics belong to the dependency. Earlier capabilities remain in regression tests.
