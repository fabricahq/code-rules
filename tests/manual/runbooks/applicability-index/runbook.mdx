# Walk through rule applicability indexes

Explore the Builds deliverable in [PR #3](https://github.com/fabricahq/code-rules/pull/3) through one retry-client example. Allow about 10 minutes. Each button runs the real builder with illustrative library data.

You will follow the same path an agent follows: **choose groups, scan rule applicability, then read the full rules**. You can repeat the chapters independently. Results appear in the **Files** panel, with a separate folder for each experiment.

## 4. Author a discoverable rule

<Command
  id="inspect-authoring"
  command="bun tests/manual/applicability-walkthrough.ts authoring"
  title="Open the shared rubric and example rule"
  successMessage="Open the two files under 04-authoring."
/>

The canonical authoring document supplies one flexible template for technology and practice rules. The example uses a broad activity trigger and a precise obligation:

| Question | Where the answer belongs |
| --- | --- |
| Is this relevant before I write code, or during review? | Required `whenToRead` metadata. For example: when planning, writing, changing, or reviewing an operation that coordinates several steps. |
| How do I implement it? | Useful choices, steps, and examples in the body. A separate Implementation heading is optional. |
| What would demonstrate compliance or a violation? | Observable evidence and boundaries in the body. A separate Validation heading is optional. |

For the retry-stage rule, understandable inline steps can comply. Extracting helpers merely to shorten a function is not the requirement. Authors should consider implementation and validation separately, while avoiding sections that repeat what the obligation already says.

Open `name-retry-stages.md` to compare its three parts: `whenToRead` triggers reading before code exists; Implementation explains when to extract details; Validation identifies evidence and exceptions.

<Check

Existing source snapshots and local rules need rule-level `whenToRead` before rebuilding. Group-level selection hints do not satisfy this requirement.

## 5. Review the result

You have inspected real output for group discovery, rule selection, replacements, exclusions, local additions, bounded index pages, and authoring guidance.

The walkthrough's assertions establish file behavior. The implementation and review chapters explain how an agent should use those files; they do not prove that an agent will select every relevant rule or comply with it.

The complete repository gate is `bun run check`. The focused walkthrough test is `runbooks test tests/manual/runbooks/applicability-index`. Imports fetching, workspace installation and stale-file removal, the CLI, and private-library migration remain separate work.
