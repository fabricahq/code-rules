# Syllabus skills: a hands-on walkthrough

This runbook builds the latest Syllabus CLI from source and walks through each new feature, one section at a time, against demo repositories it creates on your machine.

<Admonition type="warning" title="Unreleased preview build" description="This builds `claude/skills-preview`, a branch that combines the draft pull requests #117 to #126 of fabricahq/code-rules, including the rename to Syllabus. None of it is released, and commands, messages, and file formats may still change." />

**How to open it.** Install the Runbooks app as the [installation page](https://runbooks.gruntwork.io/intro/installation/) describes, and install its `runbooks` command from the app's welcome screen. Then open this folder:

```bash
runbooks open <path to your code-rules checkout>/_walkthrough/skills
```

You can also open it straight from GitHub, without a checkout:

```bash
runbooks open https://github.com/fabricahq/code-rules/tree/claude/skills-preview/_walkthrough/skills
```

Run the blocks from top to bottom. Each step uses what the steps before it created.

**What it touches.** Everything goes in one work folder, `/tmp/syllabus-skills-walkthrough` unless you choose another. Git runs with its own configuration file in that folder, so your `~/.gitconfig`, signing keys, and credential helpers are never used. Go uses your own module and build caches, so a build reuses what you've already downloaded. The demo repositories live in the work folder and are reached through a small stand-in for `ssh`, so nothing goes over the network except the clone of syllabus and Go's module downloads. The last section points `HOME` at a folder inside the work folder, for two commands only. The final block deletes the work folder.

## Create the demo repositories

The walkthrough needs three repositories, all inside the work folder:

- **acme-library**, a Syllabus library with five rules in three rule groups and five skills. One skill bundles an executable script, two cite rules, and two use another skill. The library publishes library release 1, which tags it `release/1`.
- **team-skills**, a plain Git repository of skills that isn't a library, tagged `v1.0.0`.

## Skill metadata and cited rules

A skill you author in `.syllabus/skills/<name>/` is checked before it's installed. Its `metadata` can hold three `syllabus-` keys: `syllabus-skill-type` (`playbook` or `review`), `syllabus-rules-used`, and `syllabus-skills-used`. Any other `syllabus-` key is an error, and a bare rule ID must name a rule the project authors. A source's rule in a group the source includes in full must exist, so a misspelled rule ID fails too.

When a skill cites rules, its installed copy ends with **Rules this skill applies**, which links to the project's version of each one, or says why there's none.
