Code Rules keeps a project's rule configuration, authored rules, imported libraries, and generated guidance in `.code-rules/` at the project root. Your agent starts with `.code-rules/generated/RULES.md`.

## Project layout

Your project may also have an `AGENTS.md` at its root. That file tells your agent to read the generated rules; Code Rules does not create it. For a sample instruction, see [Set up your first project](/start-here/set-up-project/#5-give-the-rules-to-your-agent).

## What to edit

| Path | What you do |
| --- | --- |
| `.code-rules/config.yaml` | Select libraries, revisions, groups, exclusions, and replacements. |
| `.code-rules/local/` | Write rules for this project, including replacements for imported rules. |
| `.code-rules/vendor/` | Review imported library files. `project sync` updates this snapshot; do not edit it. |
| `.code-rules/generated/` | Give these resolved rules and indexes to agents. `project build` or `project sync` regenerates them; do not edit them. |

An imported rule remains in `vendor/` when you replace it. Write the replacement in `local/` and name it in `config.yaml`. The replacement then appears in `generated/`. For the configuration fields, see [Configuration](/reference/configuration/).

After changing local rules or exceptions, run `code-rules project build` and `code-rules project check`. After changing a library, revision, or group selection, run `code-rules project sync` and `code-rules project check`. Commit `.code-rules/` with your project instructions so teammates can use the same rules offline.

## Project and group guides

`project init` creates `.code-rules/README.md` with setup and authoring instructions. Your project's root `README.md` stays as it was. Adding a local group creates a `README.md` beside its `_group.yaml`; the group guide is for authors and does not become a rule.

Code Rules manages the `.code-rules/README.md` guide. If you edit it, build, sync, and init refuse to replace your changes. Keep your project notes elsewhere, then regenerate the guide. `project check` reports an outdated or missing guide without changing it. For recovery details, see [Sync and recovery](/reference/sync/).

## Where agents start

Point your agent to `.code-rules/generated/RULES.md`. It lists the groups and tells the agent when to open each one. The agent should read every relevant group and each applicable rule in full. A large group index may have several pages.

| Generated path | Purpose |
| --- | --- |
| `RULES.md` | Starting point for choosing groups. |
| `groups/` | Group indexes, with full rules or links to them. |
| `rules/` | Full resolved rules, including local replacements. |
| `libraries/` | Source summaries and retained license and notice files. |
| `provenance.json` | Source revisions and rule origins for auditing. |

For agent instructions, see [Plan, write, and review](/for-agents/). For source and replacement records, see [Provenance](/reference/provenance/).

## Example: follow a rule from the index

These excerpts show the path from an index to a local rule. The generated files include more reading guidance and source details.

1. Open `.code-rules/generated/RULES.md` and use its **When to read** cue:

   ```md
   ### Testing

   **When to read this group:** When adding or changing behavior, fixing bugs, or reviewing tests.

   **Open group:** [Testing](groups/practices/testing.md)
   ```

2. Open the Testing group. A large group's index links to each full rule:

   ```md
   ### Test changed behavior

   Rule ID: `local:practices/testing/test-changed-behavior`

   **When to read:** When adding or changing externally visible behavior.

   **Read full rule:** [Test changed behavior](../../rules/local/practices/testing/test-changed-behavior.md)
   ```

3. Read `.code-rules/generated/rules/local/practices/testing/test-changed-behavior.md`:

   ```md
   # Test changed behavior

   Rule ID: `local:practices/testing/test-changed-behavior`

   ## Guidance

   When a change alters behavior that a caller or user relies on, add or update a test for that outcome.
   ```

Edit the authored rule in `.code-rules/local/practices/testing/test-changed-behavior.md`, then build again. The generated copy reflects your edit.

For the package-by-package implementation and test map, see [Inspect the implementation and tests](/for-agents/#inspect-implementation-and-tests).
