## ✨ New Features

### Read rule libraries from Go with the `coderules` package

Tools such as catalogs can now read a Code Rules library exactly as Code Rules reads it, instead of reimplementing the format. The new `github.com/fabricahq/code-rules/coderules` package parses library release tags and their release records, rule files, group metadata, and the canonical group list. It only parses: you pass it bytes or text you've already read, such as a tag message read with go-git, so it needs no Git binary, file access, or network.

```sh
go get github.com/fabricahq/code-rules/coderules@v0.3.0
```

```go
release, err := coderules.ParseReleaseTag("release/4") // 4
notes, record, err := coderules.ParseReleaseMessage("release/4", message)
for id, version := range record.Rules {
	fmt.Println(id, version) // every current rule's version in this library release
}
```

Your code can act on three errors with `errors.Is` and `errors.As`: `ErrNotReleaseTag` for a tag that isn't a library release, `*UnsupportedReleaseRecordError` for a release record in a newer format than this version reads, and `*ValidationError`, with the location and problem, for invalid input. The package follows Code Rules' version and may change before 1.0.0; these release notes will call out any breaking change to it. See the [library format](https://code-rules.fabricahq.com/reference/library-format/) and [rule versions](https://code-rules.fabricahq.com/reference/rule-versions/) references for what it reads. (#94)
