Code Rules is now **Trail Guide**, and it installs agent skills as well as rules. This release breaks existing setups: the CLI, its directory, the project configuration, the project and library layouts, and the Go module path all change; see Breaking Changes below.

## ✨ New Features

### Install skills alongside rules

Trail Guide now manages your agents' skills the way it manages rules, so every developer and agent on a project uses the same reviewed skills. Name the skills you want from each source, and `trailguide project sync` installs them into the folders your agents read:

```yaml
schemaVersion: 2
skillTargets: [claude, agents]
sources:
  fabrica:
    repository: https://github.com/fabricahq/public-rules.git
    rules: {include: [techs/go/*]}
    skills: {include: [skills/build-feature]}
```

- `skillTargets` chooses where copies go: `claude` for `.claude/skills/` and `agents` for `.agents/skills/`. Trail Guide only replaces folders it installed.
- A source can be any Git repository with skill folders, not only a rule library; set its `ref` to a tag or commit. Skills you write in `.trailguide/skills/` install too.
- `generated/SKILLS.md` lists every installed skill, what it does, and where it lives. Each installed skill links to the project's version of every rule it cites.
- `trailguide project add source` adds a source with `--rules` and `--skills` selectors, and `trailguide project list skills` lists every installed and available skill.

See [Install skills](https://trailguide.fabricahq.com/guides/install-skills/). (#120, #123, #133)

### Skills bring the skills they use

Including a skill also installs every skill it names in `trailguide-skills-used`, and the skills those use, from the same source. Declare uses a skill leaves out under `skills.uses`. Sync fails, writing nothing, when a used skill is missing or the uses form a cycle. (#124)

### Exclude or fork a source's skills

List skills to leave out under `skills.exclude`, each with a reason. To change a skill, fork it into your project:

```sh
trailguide project add skill --from fabrica:skills/fix-bug --reason 'We use our own bug workflow.'
```

The fork replaces the original, and `trailguide project update` tells you when the original changes so you can decide whether to take the change. (#125)

### Required, recommended, and offered skills

A library can now mark its skills as required, recommended, or offered under `library.skills` in its manifest. Every project that uses the library installs its required skills, and `include: [recommended]` adds the recommended ones. A project can't exclude or fork a required skill. `SKILLS.md`, `trailguide project list skills`, and the update preview show each skill's level. See [Skill levels](https://trailguide.fabricahq.com/reference/configuration/#skill-levels). (#133)

### Curated skills from other repositories

A library can now recommend a third party's skill without copying it. Declare the skill's repository in the library's own `sources` and list the skill at a level as `<source>:<skill-id>`, such as `mattpocock:skills/engineering/to-spec`. Projects fetch it from the original repository, record the commit they resolved, and show in `SKILLS.md` which library listed it. A library release doesn't lock the curated source's `ref`, so each project picks up newer commits when it runs `trailguide project update`. See [Curated skills](https://trailguide.fabricahq.com/reference/configuration/#curated-skills). (#134)

### Trail Guide keeps your AGENTS.md pointing at your rules and skills

`trailguide project init`, `build`, `sync`, and `update` now add a section to your repository's `AGENTS.md` that tells agents to read your rules and use your installed skills, and keep it current as Trail Guide's recommended wording changes. Your own text outside the section is never touched, and `trailguide project check` fails when the section is missing or outdated. If `AGENTS.md` already points to your generated rules, Trail Guide leaves it alone. To manage the file yourself, set `manageAgentsFile: false`. See [AGENTS.md section](https://trailguide.fabricahq.com/reference/configuration/#agentsmd-section). (#127, #128)

### Select rules with selectors

Each source now selects rules with `rules.include` and `rules.exclude`, which take a rule ID, a group prefix such as `techs/go/*`, a type such as `practices/*`, or `"*"`. A group prefix also takes rules the library adds to that group later. (#117)

### One layout for projects and libraries

A project keeps the rules it writes in `.trailguide/rules/` and shared files in `.trailguide/assets/`. A library uses the same layout, with its manifest in the `library:` section of `.trailguide/config.yaml`, so one repository can be both a project and a library. (#118, #119)

## ⬆️ Improvements

- `trailguide project update` lists each skill it adds, changes, or removes, flags every added or changed script, and warns you to read them before you confirm, since your agents may run them. (#122)
- `trailguide project sync`, `update`, and `check` warn when a personal skill in `~/.claude/skills`, `~/.agents/skills`, `~/.codex/skills`, `~/.grok/skills`, or `~/.copilot/skills` has the same name as a skill the project installs. For each agent that reads both copies, the warning says which one it uses, or that the agent's docs don't say. (#121)
- `trailguide project check` reports installed skills that were edited, removed, or are no longer installed, and `trailguide project build` repairs them. `trailguide library check` validates a library's skills. (#123)

## 🐛 Squashed Bugs

- Release binaries are now built with Go 1.27.2, which fixes the standard library vulnerability [GO-2026-6604](https://pkg.go.dev/vuln/GO-2026-6604). (#113)

## ⛓️‍💥 Breaking Changes

This release renames Code Rules to Trail Guide, with the `trailguide` CLI, the `.trailguide/` directory, the `<org>/.trailguide` library convention, and `trailguide_<version>_<os>_<arch>.tar.gz` release archives; requires version 2 project configuration; moves a project's own rules from `local/` to `rules/` and a library's `rule-library.yaml` and groups into `.trailguide/`; replaces `project add library` with `project add source`; and changes the managed `.trailguide/README.md` guide. Because Trail Guide is in initial development and hasn't been publicly announced, we're not including upgrade instructions. (#117, #118, #119, #120, #126, #128, #138)

Compatibility with what Code Rules wrote:

- Project commands still work in `.code-rules/` and warn you to run `git mv .code-rules .trailguide`.
- Library commands refuse to run until you run `git mv .code-rules .trailguide`.
- Library releases published from `.code-rules/` stay readable, so projects keep their rule versions.
- `trailguide project init`, `build`, `sync`, and `update` replace an older, unedited managed guide with the new one, but refuse to overwrite one you edited.

**Go importers:** the module path moved from `github.com/fabricahq/code-rules` to `github.com/fabricahq/trailguide`, and the `coderules` package is now `trailguide`. Import `github.com/fabricahq/trailguide/trailguide` instead of `github.com/fabricahq/code-rules/coderules`. (#126, #138)
