Code Rules is now **Syllabus**, and it installs agent skills as well as rules. This release breaks existing setups: the CLI, its directory, the project configuration, the project and library layouts, and the Go module path all change. See [Breaking changes](#️-breaking-changes).

## ✨ New Features

### Install skills alongside rules

Syllabus now manages your agents' skills the way it manages rules, so every developer and agent on a project uses the same reviewed skills. Name the skills you want from each source, and `syllabus project sync` installs them into the folders your agents read:

```yaml
schemaVersion: 2
skillTargets: [claude, agents]
sources:
  fabrica:
    repository: https://github.com/fabricahq/public-rules.git
    rules: {include: [techs/go/*]}
    skills: {include: [skills/build-feature]}
```

- `skillTargets` chooses where copies go: `claude` for `.claude/skills/` and `agents` for `.agents/skills/`. Syllabus only replaces folders it installed.
- A source can be any Git repository with skill folders, not only a rule library; set its `ref` to a tag or commit. Skills you write in `.syllabus/skills/` install too.
- `generated/SKILLS.md` lists every installed skill, what it does, and where it lives, and links to the project's version of each rule a skill cites.
- `syllabus project add source` adds a source with `--rules` and `--skills` selectors, and `syllabus project list skills` lists every installed and available skill.

See [Install skills](https://code-rules.fabricahq.com/guides/install-skills/). (#120, #123, #133)

### Skills bring the skills they use

Including a skill also installs every skill it names in `syllabus-skills-used`, and the skills those use, from the same source. Declare uses a skill leaves out under `skills.uses`. Sync fails, writing nothing, when a used skill is missing or the uses form a cycle. (#124)

### Exclude or fork a source's skills

List skills to leave out under `skills.exclude`, each with a reason. To change a skill, fork it into your project:

```sh
syllabus project add skill --from fabrica:skills/fix-bug --reason 'We use our own bug workflow.'
```

The fork replaces the original, and `syllabus project update` tells you when the original changes so you can decide whether to take the change. (#125)

### Required, recommended, and offered skills

A library can now mark its skills as required, recommended, or offered under `library.skills` in its manifest. Every project that uses the library installs its required skills, and `include: [recommended]` adds the recommended ones. A project can't exclude or fork a required skill. `SKILLS.md`, `syllabus project list skills`, and the update preview show each skill's level. See [Skill levels](https://code-rules.fabricahq.com/reference/configuration/#skill-levels). (#133)

### Syllabus keeps your AGENTS.md pointing at your rules and skills

`syllabus project init`, `build`, `sync`, and `update` now add a section to your repository's `AGENTS.md` that tells agents to read your rules and use your installed skills, and keep it current as Syllabus's recommended wording changes. Your own text outside the section is never touched, and `syllabus project check` fails when the section is missing or outdated. If `AGENTS.md` already points to your generated rules, Syllabus leaves it alone. To manage the file yourself, set `manageAgentsFile: false`. See [AGENTS.md section](https://code-rules.fabricahq.com/reference/configuration/#agentsmd-section). (#127, #128)

### Select rules with selectors

Each source now selects rules with `rules.include` and `rules.exclude`, which take a rule ID, a group prefix such as `techs/go/*`, a type such as `practices/*`, or `"*"`. A group prefix also takes rules the library adds to that group later. (#117)

### One layout for projects and libraries

A project keeps the rules it writes in `.syllabus/rules/` and shared files in `.syllabus/assets/`. A library uses the same layout, with its manifest in the `library:` section of `.syllabus/config.yaml`, so one repository can be both a project and a library. (#118, #119)

## ⬆️ Improvements

- `syllabus project update` lists each skill it adds, changes, or removes, flags every added or changed script, and warns you to read them before you confirm, since your agents may run them. (#122)
- `syllabus project sync`, `update`, and `check` warn when a personal skill in `~/.claude/skills`, `~/.agents/skills`, or `~/.codex/skills` has the same name as a skill the project installs, and say which copy each agent uses. (#121)
- `syllabus project check` reports installed skills that were edited, removed, or are no longer installed, and `syllabus project build` repairs them. `syllabus library check` validates a library's skills. (#123)

## 🐛 Squashed Bugs

- Release binaries are now built with Go 1.27.2, which fixes the standard library vulnerability [GO-2026-6604](https://pkg.go.dev/vuln/GO-2026-6604). (#113)

## ⛓️‍💥 Breaking Changes

Code Rules is renamed Syllabus: the CLI is `syllabus`, projects and libraries keep their files in `.syllabus/`, an organization's shared library is `<org>/.syllabus`, and release archives are named `syllabus_<version>_<os>_<arch>.tar.gz`. Projects still in `.code-rules/` keep working and warn you to run `git mv .code-rules .syllabus`, library commands refuse to run until you do, and library releases published from `.code-rules/` stay readable. Project configuration moves to version 2, which earlier versions can't read and which this version requires; a project's own rules move from `local/` to `rules/`; a library's `rule-library.yaml` and root-level groups move into `.syllabus/`; `project add library` becomes `project add source`; and the managed `.syllabus/README.md` guide describes the new layout and skills, which `init`, `build`, `sync`, and `update` install over an older, unedited guide but refuse to install over one you edited. (#117, #118, #119, #120, #126, #128)

**Go importers:** the module path moved from `github.com/fabricahq/code-rules` to `github.com/fabricahq/syllabus`, and the package `coderules` is now `syllabus`. Import `github.com/fabricahq/syllabus/syllabus`. (#126)

Because Syllabus is in initial development and hasn't been publicly announced, we're not including upgrade instructions.
